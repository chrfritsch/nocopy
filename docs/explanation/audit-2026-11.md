# Correctness audit, 2026-11-09/10: findings and plan

An audit of the three riskiest areas (zero-copy values, cross-process concurrency, the plan/write split) for bugs the suite
misses. This page records the invariants it checked against, what it found and fixed, what it ruled out and why, and what is
still open. It is a snapshot; the lasting rules live in [Architecture](architecture.md#invariants-worth-remembering).

State: five bugs found, each reproduced first and fixed with its test. The audit is **not finished**: see [Plan](#plan).

## Invariants

Written down before any code changed. Each finding below names the one it broke.

Arena
- A1. The arena knows nothing of PHP or Valkey; the layers above change it only through its calls.
- A2. No allocation and no user code while a shard lock is held.
- A3. One shard lock at a time, except `nocopy_clear` and the atoms' `segments_use` (all, in index order).
- A4. A segment changes shard only through the pool: zeroed record, `owner = 0` (release), claimed by CAS.
- A5. Nothing in a segment is dereferenced before its pin is published and the slot re-checked. A worker slot's pin bitmap,
  `agen` and counters are written by the slot's owner only; a claim resets them.
- A6. `reclaim` collects the DEAD set, fences, then reads the pins.
- A7. A live entry is reachable from exactly one slot; the slot table is the truth after a dead holder (`repair`).
- A8. A slot table holds at most `cap` entries; a reader's miss counts only under an even, unchanged `mseq`.
- A9. An entry's size is set before `used` covers it; sizes are multiples of 8.
- A10. Only the owning shard, under its lock, changes a segment's state; DEAD ends only in its `reclaim`.
- A11. `seq` grows per shard; `(address, seq)` names one version of a key.
- A12. A `wip` record changes only under its entry's shard lock; a dead writer's unfinished entry is rolled back.
- A13. An entry points only at atoms of the generation its writer announced, with its segment's bit set before the view ends;
  an atom is never written after admission; a half is wiped only with no view and no segment bit on it.
- A14. A lease is dropped only by the worker slot that holds it.

Values
- V1. Every pointer in a block points into the block, to the arena's empty array or to an atom. Nothing of a process
  (its binary's addresses) is in shared memory at any instant.
- V2. Block structures are immutable to PHP: refcount 2 (3 for deduped strings), `IS_ARRAY_IMMUTABLE`, `IS_STR_INTERNED`
  but never `IS_STR_PERMANENT`, zval type flags 0.
- V3. Array keys, and strings up to 64 bytes inside arrays and objects, carry their hash for the entry's whole life.
  Other strings may be unhashed; readers hash them (an idempotent write).
- V4. Written bytes equal planned bytes; the tape is consumed exactly; writing decides nothing.
- V5. No user code during a planning walk or a write; hooks run between passes; planning's holds are released after the commit.
- V6. A reader hands out, and frees, only fully built values: every slot of every object set before any release or user code;
  no graph marker reaches userland.
- V7. A zero-copy value stays pinned until post-deactivate; copy mode hands out no arena pointer.
- V8. Kept copies are per `(address, seq)`; integers changed in place are never kept.
- V9. Class fingerprints stand for the type checks `unserialize()` makes.

Valkey
- K1. Local write first, then `SET`; the listener bumps `inval_gen` before it drops; a fill reads `inval_gen` before its
  `GET` and drops its copy if it moved.

## Tooling added

- **`NC_ASSERT` and `block_check`** (`6adca78`). The written == planned assertion existed as a `ZEND_ASSERT`, which the release PHP of
  every `./dev` image compiles out: no command ever ran it, the fuzzer included. It is now on in `./dev asan`, `./dev fuzz`
  (`-DNOCOPY_DEBUG`) and under a debug PHP. `block_check` walks every block after it is written and checks V1, V2, V3.
- **`./dev debug [tests]`, `./dev debug fuzz`** (`6adca78`): the suite and the fuzzer on PHP built with `--enable-debug`
  (`docker/Dockerfile.debug`): the engine's own assertions, among them a refcount changed on an immutable value.
- **`AR_HOOK` and `tests/c/crash.c`** (`5056822`): named steps in the arena's write paths, compiled only with `-DNOCOPY_HOOKS`.
  `crash.c` kills a forked worker at 39 steps (9 hit counts, a 4 MB one-shard and a 16 MB two-shard arena: 702 cases, the
  worker dies in 455) and checks what the survivor finds: values it kept pinned untouched, every value intact, slot tables,
  segments, live bytes, pending counts and atom tables consistent, the workload running on, every segment back after a clear,
  both atom halves turning over. `crash <point> <hit> <mb>` replays one case. Part of `./dev c`.

## Ruled out

- **Plan == write (area 3).** With the assertion and `block_check` compiled in: `./dev asan` 83 passed, `./dev debug` 82 passed,
  `./dev debug fuzz 20000` and `./dev fuzz 20000` clean in both modes (seeds 3234402563, 2529788101), no assertion fired.
  By reading: every size term in `nocopy_plan.c` has its `take()` in `nocopy_write.c` (array header + `HT_PACKED_USED_SIZE` or
  `map_size`, where `map_mask == nTableMask` makes `HT_USED_SIZE` the same number; object nodes by `kind_nprops` + dyn; the
  graph head; class names twice); both walks branch on the same facts (element count 0, packed, `Z_REFCOUNT > 1` of a
  reference, which nothing changes between the last pass and the write); every other decision is on the tape. A reference
  cycle ends at the second sighting; a reference held once is patched from `T_ONCE` in place.
- **A nested write during a read dropping the reader's pins.** `nocopy_put_begin` drops transient pins only with
  `pin_refs == 0`; a fetch holds a borrow across autoloaders and `__wakeup`/`__unserialize`, so the graph stays pinned.
- **Runs of segments.** A reader pins the head; only the head is ever DEAD; `give` frees the whole run.
- **The `mseq` seqlock and pin ordering on arm64, by reading.** Readers use acquire loads (`ldar`), which later loads cannot
  pass; the writer's odd store is followed by a full fence and release stores. Pins are seq_cst store + fence against
  `reclaim`'s fence + seq_cst loads. Not yet run on arm64 hardware: see Plan.
- **Atoms.** Dekker between a view's announcement and `WIPING`; a half-done admission or rotation leaves a state the next one
  builds on (all atom steps killed in `crash.c`). Counter wrap: `gen` reaches the `WIPING` bit after 2^31 rotations, each of
  which needs a half filled and unreferenced; not reachable in an arena's life, and not guarded.
- **Leases.** A lease is one struct assignment under the table lock; any torn state reads as free or as held by a dead owner.
- **Valkey fill guard.** A fill that read before an invalidation either sees `inval_gen` moved after its put, or put before the
  listener's drop, which follows the bump. Local writes precede the `SET`, so a later remote write's push always removes them.
  A request stays `synced` for its whole length, so a listener that dies mid-request serves it stale data until it ends: by design.
- **Userland writes into the arena, by reading.** Arena zvals carry no refcount flag, arrays have refcount 2, so `sort`,
  `array_walk`, `foreach` by reference, `extract(EXTR_REFS)`, `ArrayObject` separate first; `json_encode`, `var_dump`,
  `serialize` skip recursion marks on immutable or non-refcounted arrays. Known writes: a string's hash on first use (V3) and
  `IS_STR_VALID_UTF8`, both idempotent. `./dev debug` (which asserts on a refcount change of an immutable value) passed the suite.
  Test 093 checks it byte for byte.

## Plausible, not reproduced

- **A forked child's inherited pins.** `nocopy_after_fork` publishes the parent's bits in the child's new slot without a
  re-check. If the parent drops a pin between `fork` and that publish and the segment is reclaimed in that gap, the child
  believes it holds a pin it never published. Needs a zero-copy request that forks while holding values; microseconds wide.
- **`nocopy_stats()['pinned_segments']`** now counts a dead worker's bits until its slot is claimed again (fix 4 no longer
  clears them). Cosmetic; `reclaim` ignores them.

## Plan

In order. Each item ends with its commit passing `./dev test`, `layers`, `stress 30`, `c 5`, `novalkey`, `shm`.

1. **`./dev ci` end to end.** Every fix passed the per-commit gate (`layers`, `test`, `stress 30`, `c 5`, `novalkey`, `shm`;
   the last one run on `9f5b4cf`). The ci steps run one by one on `d1e7ba2` (before bug 5): `layers`, `test`, `novalkey`, `asan`,
   `clang`, `stress 30`, `c 5`, `fuzz`, `shm`, `pie`, `zts`, `frankenphp`, `debug`, `debug fuzz` passed; `tidy` failed there
   (`NC_ASSERT` gave release builds no assumption) and passes since `NC_ASSERT` became `ZEND_ASSUME`; `symfony` and `apcu` could
   not start in the sandbox (composer and a `git clone` of APCu have no network from containers). Owed on a normal host:
   `./dev ci` in one go on the final tree, `symfony` and `apcu` in particular (bug 5's fix touches copy mode's templates).
2. **Userland operations on fetched values** (area 1): done as test 093 for modify, unset, reference-take, the sorts,
   `json_encode`, `serialize`, `var_dump`, `foreach` by reference, `extract` (also `EXTR_REFS`), `array_walk`, the array
   functions that take a reference, string offsets, object property writes, casts and clones, on a plain array, a string alone
   and a graph (object with a cycle, enum, date, shared reference): in both modes the arena file under `/dev/shm` is
   byte-identical before and after (no nocopy call in between), a second held copy and a fresh fetch equal the original. Also
   passes on the debug PHP. Open: strings stored unhashed (longer than 64 bytes: the hash write is expected there), and the
   same value held across an overwrite and a full churn of the arena (004 covers pins, not these operations).
3. **Fuzzer additions** (area 3): done: values arriving as references (`nocopy_put_multiple` of foreach-by-reference
   elements) and fetched values written all over before the next fetch (which found bug 5). Open: hooks that replace or grow
   parts of the graph or throw mid-plan (tests 068, 074 cover fixed cases), values around half a segment and a whole one,
   an arena nearly full. A full `./dev fuzz 20000` and `./dev debug fuzz 20000` with the extended fuzzer is still owed
   (3,000 iterations ran clean in both modes).
4. **`crash.c` coverage**: no worker is killed at `move.linked`, `merge.moved`, `rebalance.unlocked`, `rebalance.merged`,
   `rotate.gen` with the current seeds (it prints them). Tune the workload until each is reached, then make an unreached
   point a failure. Add kills in the PHP layer (`nc_write` of a big block, between `nocopy_atom_begin` and the commit).
5. **arm64**: build and run `tests/c` (plain, TSan, crash) and `stress 30` on arm64. This audit ran on amd64 only.
6. **`./dev ab main 7`** for `7e0682c` (rebase, the merge path) and `5056822` (`ar_pool_pinned`): neither is on the fetch or
   store fast path, but both run under the shard lock; numbers into the commit notes and [design decisions](design-decisions.md).
7. **Decide** whether `./dev debug` joins `./dev ci` (it builds PHP once per image: minutes without a layer cache).
8. **The forked child's pins** (above): publish with a re-check, or drop inherited transient pins in the child.

## Notes on this run

Ran in a cloud sandbox on amd64, not the usual arm64 Docker host. `pecl` could not reach its channel from build containers
there, so the images were built from downloaded tarballs with the same steps; `docker/Dockerfile.debug` as committed uses
`pecl download` and has not been built unmodified. The session was restarted once mid-run.
